# Brand guidelines system

Guidelines are done when every rule carries a rationale and a misuse example, every value is
measured or proofed (never typed from memory), the assets ship in a versioned `brand/` folder, and
an audit procedure exists that can fail a touchpoint with numbers. A PDF of pretty pages is not a
system; a system still works when the logo is hidden.

Tool: [brand_check.py](scripts/brand_check.py). `pairs` (stdlib) builds the accessibility table
from DTCG tokens (aliases resolved; hex, srgb or oklch values); `drift` (Pillow) maps a
screenshot's dominant colours to the nearest token by OKLab distance and checks logo clear space.

```bash
STACK="$HOME/.claude/stack"; [ -d "$STACK" ] || STACK="${CLAUDE_PROJECT_DIR:-.}"
BC="$STACK/.claude/skills/brand-guidelines-system/scripts/brand_check.py"
PY="$STACK/.venv/bin/python"; [ -x "$PY" ] || PY=python3          # drift needs Pillow
python3 -I "$BC" pairs brand/color/brand.tokens.json color.text.body/color.bg.page color.paper/color.bg.action
"$PY" -I "$BC" drift shot.png brand/color/brand.tokens.json --k 12 --logo-box 20,20,120,60 --clear 24
```

Exit 1 means a pair under 3:1, an OFF colour above `--min-share` (default 0.5 % of pixels) or a
clear-space breach, so the same commands gate CI next to the token build.

## 1. Required sections, in this order

| # | Section | Must contain | Source of truth |
|---|---|---|---|
| 1 | Logo suite | versions, clear space, minimum sizes, backgrounds, misuse sheet | `logo/` masters |
| 2 | Colour | per-colour spec table, usage-proportion bar, light and dark roles | `color/*.tokens.json` + proof log |
| 3 | Typography | families, weights, fallbacks, scale tokens, role table, licences | type tokens, `fonts/` |
| 4 | Grid and spacing | spacing scale, grid per medium, radii | spacing tokens |
| 5 | Imagery | photography rules, illustration sheet, generated-image policy | `imagery/refs/` |
| 6 | Iconography and data-viz palette | icon grid and stroke; categorical, sequential, diverging sets | icon set, tokens |
| 7 | Motion (only if the brand moves) | duration and easing tokens, reduced-motion rule | motion tokens |
| 8 | Voice and tone | 3-4 "we are X, not Y" attributes with examples | copy deck |
| 9 | Accessibility statement | approved pairs, measured ratios, permitted sizes | generated by `pairs` |
| 10 | Asset manifest and changelog | folder map, versions, owners, what changed | `brand/` tree, CHANGELOG |

Write every rule as four parts: **rule**, **why**, **do** (example), **don't** (misuse). Rules
without a why are ignored by designers and over-applied by agents.

## 2. Logo suite and usage

Suite: primary lockup, horizontal and stacked, mark only, wordmark only, one-colour black and
white, reversed, and a simplified small-size mark for 16-48 px (favicon, app icon). Masters are SVG
with outlined type; print masters are PDF/X-4 in CMYK and in the spot colour (`print-prepress-pdfx`).

Clear space: define a unit from the logo itself so it scales with it, e.g. x = cap height of the
wordmark (or the width of the mark's counter). Required clear space = 1x on every side; 0.5x only
inside UI chrome such as an app bar. Show the x module on the spec drawing.

Minimum sizes: render candidates and take the smallest size where counters stay open and the
thinnest stroke is at least 1 px on screen and 0.25 pt in print. Record the derivation.

| Version | Screen min width | Print min width | Below the minimum |
|---|---|---|---|
| Primary horizontal | 120 px | 30 mm | switch to stacked or mark |
| Stacked | 80 px | 20 mm | switch to mark |
| Mark only | 24 px | 10 mm | use the simplified favicon mark |
| Wordmark only | 96 px | 25 mm | drop the tagline below 160 px |

(Example values; every brand derives its own.)

Allowed backgrounds: light brand surfaces (full colour), dark brand surfaces (reversed), photos only
where the logo-to-background contrast at the worst pixel is at least 3:1, otherwise on a solid panel.
Logotypes are exempt from WCAG 1.4.3, so the 3:1 floor is a brand rule for recognisability; measure
it the way `visual-accessibility-audit` measures text over images.

Misuse grid, generated from the master SVG so it updates when the logo does:

| Misuse | How to build the "don't" cell |
|---|---|
| Stretch or squash | `<use href="#logo" transform="scale(1.4 1)"/>` |
| Recolour | off-palette fill, gradient fill, or each part a different brand colour |
| Effects | drop shadow, glow, bevel or outline stroke via `filter` / `stroke` |
| Rotation or skew | `transform="rotate(-12)"` or `skewX(15)` |
| Crowding | a headline or another logo inside the 1x band |
| Low contrast | full-colour logo on a mid-tone or busy photo (< 3:1 at the worst pixel) |

Do/don't sheet layout: 3 × 3 equal cells; row one shows three correct uses with a check mark, rows
two and three the six misuses with a cross and a 3-6 word caption ("Don't stretch the logo"). Add
real misuses found during audits (section 10) as extra cells; they teach better than invented ones.

## 3. Colour specification

One spec block per brand colour:

| Field | Example: brand pink, action role | Rule |
|---|---|---|
| Role | primary action, highlighted series | one role per colour, mapped to semantic tokens |
| HEX / RGB | #D63151 / 214 49 81 | sRGB master for screens |
| OKLCH | oklch(0.581 0.199 15.7) | source of ramps and dark-mode variants (`oklch-palette-ramps`) |
| CMYK, PSO Coated v3 (FOGRA51) | the approved build from proof P-012 | name the profile on every CMYK value |
| CMYK, GRACoL 2013 (CRPC6) | the approved build from the US proof | one value per printing condition |
| Pantone Coated / Uncoated | picked from the printed guides | C and U are separate picks; U prints lighter and duller |
| Dark-surface variant | lighter L, same hue, re-measured on the dark surface | listed in the pairs table |

Print values, procedure:

1. Convert the sRGB master into each printing condition's ICC profile (relative colorimetric with
   black point compensation). This is a starting point, not a spec.
2. Proof candidate builds and Pantone chips on the real stock (contract proof to ISO 12647-7 or a
   press proof) and judge them under D50 light against the screen master and the previous print.
3. Publish only the approved build with profile, proof ID and date; keep the ICC start values in
   the proof log. State in the guidelines that conversions are approximations confirmed by proofs.
4. Pantone: choose visually from the current Coated and Uncoated guides, never from a converter or
   a monitor.

Usage-proportion bar (how much of a typical layout each colour takes):

```html
<div role="img" aria-label="Colour proportions: paper 60%, ink 25%, brand pink 10%, accent 5%"
     style="display:flex;height:40px;border-radius:6px;overflow:hidden;border:1px solid #D0D0D0">
  <div style="flex:60;background:#FFFFFF"></div><div style="flex:25;background:#19172E"></div>
  <div style="flex:10;background:#D63151"></div><div style="flex:5;background:#0072B2"></div>
</div>
```

Tokens: primitive → semantic → component tiers in DTCG `.tokens.json`, a light and a dark value per
semantic token (`design-tokens-dtcg`). Ramps and their measured steps come from `oklch-palette-ramps`.

## 4. Typography

| Role | Family | Weight | Size token | Line height | Fallback stack |
|---|---|---|---|---|---|
| Display | Brand Sans | 700 | `font.size.4xl` | 1.1 | system-ui, sans-serif |
| Headings | Brand Sans | 600-700 | `font.size.3xl`-`xl` | 1.2 | system-ui, sans-serif |
| Body | Brand Text | 400 | `font.size.md` | 1.5 | Georgia, serif |
| UI labels | Brand Sans | 500 | `font.size.sm` | 1.3 | system-ui, sans-serif |
| Data and code | Brand Mono | 400 | `font.size.sm` | 1.4 | ui-monospace, monospace |

Fallbacks: list a metric-matched local face before the generic family (an `@font-face` on a
`local()` system font with `size-adjust`, `ascent-override` and `descent-override` computed from
both fonts' metrics) so a late webfont does not shift the layout.

Licence status per medium (read the EULA; desktop licences rarely cover web or apps):

| Family | Desktop and print | Web | App embedding | PDF embedding | Video |
|---|---|---|---|---|---|
| Inter (SIL OFL 1.1) | yes | yes | yes | yes | yes |
| Commercial family (example) | 5 seats | 1 domain, page-view tier | not licensed: buy or substitute | per fsType flag | check EULA |

Scale tokens, ratios and responsive steps: `type-scale-systems`.

## 5. Grid and spacing

- Spacing scale on a 4 or 8 px base (4, 8, 12, 16, 24, 32, 48, 64) as `space.*` tokens; radius
  and elevation tokens beside it.
- Grid per medium: 12 columns for web, module and baseline grids for print and posters
  (`layout-grids-posters-editorial`), platform safe zones for social formats.
- Rationale example: "8 px steps, because every component then aligns on 4K, 2x and 1x screens."

## 6. Imagery direction

| Aspect | Rule (example brand) | Why |
|---|---|---|
| Light | soft directional daylight; no on-camera flash | calm, credible |
| Palette | neutral and warm settings, at most one brand-pink accent | the brand colour keeps meaning |
| Subject distance | mid-shots and hands-at-work details; no distant crowds | human scale |
| Crop | subject on a third, empty side for type; survives 1:1, 4:5 and 16:9 | one shoot serves every format |
| Representation | real range of ages, bodies, skin tones, abilities; consented people | audience sees itself |
| Retouching | keep skin texture, no body reshaping, one colour-grade preset | honesty, consistency |

Illustration style sheet: one stroke weight (2 px at 1x), corner radius equal to the UI radius,
palette subset (ink, pink, two neutrals), flat fills with one shadow tone, one perspective (front
or 30° isometric), fixed figure proportions; each rule shown as a do/don't pair.

Generated-image policy (paste into the guidelines):

1. Allowed models: only those routed by the stack's image tools (`image-generation`,
   `image-editing`), named with version; anything else needs the brand owner's approval.
2. Mandatory review: every generated or AI-edited image passes a human brand review (and a
   `visual-review` score) before use; reviewer and date are logged.
3. Disclosure: label generated imagery wherever law, platform rules or the brand's own policy
   require; keep provenance metadata (C2PA Content Credentials) when the tool writes it.
4. No real-person likeness: no public figures, staff or customers without written consent, no
   "in the style of" a living artist, no third-party logos.
5. Style anchor: 2-3 canonical, rights-cleared references in `imagery/refs/` plus one style
   sentence appended verbatim to every prompt (`image-brief-writing`), for example:
   > Editorial photograph, soft window light from the left, warm neutral palette with a single
   > brand-pink (#D63151) accent, shallow depth of field, people mid-task and unposed, generous
   > empty space in the upper third for type.
6. Provenance log per asset: model, prompt, seed, date, reviewer, placements.

## 7. Iconography, data-viz palette, motion

- Icons: one set with one grid, stroke and corner radius (`icon-system-design`); filled and
  outlined variants never mixed in one context.
- Data-viz: categorical set of at most 7, CVD-checked, brand colour reserved for the highlighted
  series; a sequential ramp from one brand hue in OKLCH; a diverging pair around a neutral
  midpoint (`chart-design-encoding`).
- Motion: duration tokens (100-150 ms micro, 200-300 ms component, 300-500 ms page), easing tokens
  (standard, enter, exit), at most one signature movement, and a `prefers-reduced-motion` fallback.

## 8. Voice and tone

| We are | Not | Headline | CTA | Error message |
|---|---|---|---|---|
| clear | clinical | "Reports your team actually reads" | "Start free trial" | "We couldn't save your changes. Check your connection and try again; your draft is safe." |
| confident | loud | "Close the month in two days" | "See how it works" | never "FATAL ERROR!!!" |
| warm | cute | "Welcome back, Ana" | "Pick up where you left off" | never "Oopsie! Something went boom" |
| precise | pedantic | "Exports to CSV, XLSX and PDF" | "Export CSV" | "File too large: 52 MB, limit 50 MB. Split or compress it." |

Rules: buttons are verbs naming the outcome (never "Submit" or "Click here"); errors say what
happened, why if known, and what to do next, without blame; tone shifts with context (lighter in
celebration, calmer in errors, plain in legal).

## 9. Accessibility statement (generated, never typed)

List every intended foreground/background pair, including states, dark mode and logo backgrounds,
run `pairs`, and publish the table verbatim with the token version and date. Permitted use follows
WCAG 2.2: at least 4.5:1 for all text (7:1 for AAA); 3:1 to 4.5:1 only for large text (at least
24 px, or 18.66 px bold), UI components and graphics; under 3:1 decorative only.

Real output on the example tokens (`color.text.muted` aliases `gray.500`, `bg.action` aliases
`pink.600`):

| Foreground | Background | Ratio | Permitted |
|---|---|---|---|
| color.text.body #19172E | color.bg.page #FFFFFF | 17.45 | all text, AA and AAA |
| color.paper #FFFFFF | color.bg.action #D63151 | 4.75 | all text AA; large text AAA |
| color.paper #FFFFFF | color.pink.500 #E94560 | 3.83 | large text >= 24 px or >= 18.66 px bold, UI and icons |
| color.text.muted #6B7280 | color.bg.page #FFFFFF | 4.83 | all text AA; large text AAA |
| color.gray.400 #9CA3AF | color.bg.page #FFFFFF | 2.54 | decorative only |

Statement line: "Every text pair in this system meets WCAG 2.2 AA (1.4.3); pairs marked large-text
only never carry body text. Measured with brand_check.py on tokens v2.3.0, 2026-10-19."
Contrast fixes (moving OKLCH L at fixed hue and chroma): `visual-accessibility-audit`.

## 10. Brand audit procedure

1. Inventory touchpoints: key web pages and app screens, social templates, decks, email, print.
2. Capture: the `browser-operator` agent screenshots each page at fixed viewports (1440 × 900 and
   390 × 844), light and dark; PDFs rendered at 150 ppi; print scanned or photographed under D50.
3. Colour drift: crop photos and illustrations out first (they are legitimately off-palette), then
   run `drift` per capture. Thresholds on deltaE_OK to the nearest token: up to 0.02 match (about
   one just-noticeable difference), up to 0.05 near (tints, compression, anti-aliasing), above
   0.05 OFF.
4. Logo: `--logo-box x0,y0,x1,y1 --clear <unit px>` with the clear-space unit at rendered size;
   check version, background and minimum size by eye.
5. Type: compare computed font families, weights and sizes (browser `getComputedStyle`,
   `document.fonts`) with the role table; flag fallback fonts actually rendering.
6. Accessibility: measure rendered pairs (`visual-accessibility-audit`).
7. Score 0-2 per criterion, report the total and fixes ordered by reach × severity.

| Criterion | 2 | 1 | 0 |
|---|---|---|---|
| Colour | every dominant colour match or near | OFF colour under 10 % of pixels | OFF primary or OFF over 10 % |
| Logo | right version, clear space, size | one minor breach | distorted, recoloured or illegible |
| Typography | families, weights and scale per spec | off-scale sizes or a fallback rendering | wrong family |
| Imagery | follows the rules or policy | partly | contradicts them, or unreviewed AI image |
| Voice | matches the attributes | mixed | off-brand |
| Accessibility | all pairs in the approved table | 1-2 failing pairs | systemic failures |
| Hide-the-logo | recognisable | partly | not recognisable |

Pass: at least 11 of 14 with no zero.

Worked example (landing-page capture, 480 × 300 px, tokens as in section 9):

```text
$ "$PY" -I "$BC" drift landing.png brand.tokens.json --k 8 --logo-box 20,20,120,60 --clear 24
share   colour   nearest token              dE_OK  verdict
 52.8%  #FFFFFF  color.paper #FFFFFF        0.000  match
 23.8%  #1B1830  color.ink.900 #19172E      0.006  match
  7.6%  #3B82F6  color.gray.500 #6B7280     0.180  OFF
  6.9%  #D9365A  color.pink.600 #D63151     0.014  match
  6.1%  #6B7280  color.gray.500 #6B7280     0.000  match
  2.8%  #E94560  color.pink.500 #E94560     0.000  match
clear space 24 px around 20,20,120,60: 9.58% foreign pixels -> BREACH
```

Score: colour 1 (an off-palette blue panel, 7.6 %), logo 1 (a nav item inside the clear space),
typography 2, imagery 2, voice 1 (the CTA reads "Submit"), accessibility 1 (helper text in
`gray.400`, 2.54:1), hide-the-logo 2: **10/14, fail**. Fixes by reach: replace the blue panel
with `color.bg.action` or a neutral surface; move the nav item at least 24 px from the logo; set
helper text to `color.text.muted` (4.83:1); rename the CTA "Start free trial". Re-run; expect 14/14.

## 11. Application checklist for a new piece

- [ ] Logo version suits the background; clear space and minimum size respected.
- [ ] Only palette tokens; proportions roughly follow the usage bar; brand colour keeps its role.
- [ ] Type from the role table and scale tokens; at most two families; fallbacks not rendering.
- [ ] Spacing on the scale, aligned to the grid of the medium.
- [ ] Imagery follows the photo rules, or the generated-image policy with review logged.
- [ ] Icons from the set; charts use the data-viz palette.
- [ ] Headline, CTA and errors follow the voice table.
- [ ] Every colour pair appears in the approved accessibility table.
- [ ] Export per medium (print via `print-prepress-pdfx`); file named and stored per the manifest.
- [ ] Hide-the-logo test: cover the logo; someone who knows the brand still identifies the piece
      from colour proportions, type, imagery, layout rhythm and voice. If not, strengthen the
      distinctive assets rather than adding more logos.

## 12. Delivery layout

```text
brand/
  README.md                      how to use the folder, owners, current version
  CHANGELOG.md                   semver: MAJOR logo or colour change, MINOR new assets, PATCH fixes
  guidelines/index.html          the guidelines page (or a shared doc); PDF export is secondary
  logo/svg/  logo/png/@1x,@2x,@3x  logo/print/*.pdf (PDF/X-4, CMYK and spot)  logo/misuse-sheet.svg
  color/brand.tokens.json        DTCG primitives and semantic tokens, light and dark
  color/print-specs.md           approved CMYK per profile, Pantone C/U, proof IDs and dates
  fonts/<family>/                font files plus LICENSE per medium
  templates/                     slides, social, documents, email, letterhead
  imagery/refs/                  2-3 canonical references with rights notes
  imagery/style-sentence.txt     the verbatim sentence for image models
  imagery/policy.md              generated-image policy and provenance log
  icons/                         SVG set and sprite
```

Guidelines ship as an HTML page or shared doc (searchable, linkable, accessible, current), not as
a PDF only. Every release gets a changelog entry: version, date, what changed, why, migration
note ("pink.500 → pink.600 for buttons: 3.83 → 4.75:1").

## Pitfalls

- CMYK values copied from an automatic conversion and never proofed; Pantone picked on screen.
- Rules with no rationale, and no misuse examples, so every reader invents their own.
- Guidelines that ignore dark mode, small sizes (favicon, 16 px), one-colour print or embroidery.
- An accessibility table typed by hand that silently drifts from the tokens.
- Fonts licensed for desktop only, then used on the web or in an app.
- Generated imagery without review, disclosure decisions or a provenance log.
- A system that only works when the logo is present (fails the hide-the-logo test).
- PDF-only guidelines with no versioning: nobody knows which copy is current.
