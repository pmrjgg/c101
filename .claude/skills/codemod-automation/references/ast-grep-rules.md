# ast-grep rule reference

Checked against ast-grep 0.51.0 (`uvx --from ast-grep-cli ast-grep --version`). The binary is
`ast-grep`; the `sg` alias prints a deprecation warning in this version.

## Project layout

```text
tools/codemods/
  sgconfig.yml            # ruleDirs, testConfigs, utilDirs
  rules/*.yml             # one or more rules per file, separated by ---
  rule-tests/*-test.yml   # valid / invalid cases per rule id
  rule-tests/__snapshots__/*-snapshot.yml   # generated by `ast-grep test -U`
```

```yaml
# sgconfig.yml
ruleDirs: [rules]
testConfigs:
  - testDir: rule-tests
```

## Rule anatomy

| Key | Meaning |
|---|---|
| `id` | unique rule id; `--filter <regex>` selects by id |
| `language` | `python`, `typescript`, `tsx`, `javascript`, `go`, `rust`, `java`, `kotlin`, `c`, `cpp`, ... |
| `severity` | `error` (non-zero exit in `scan`), `warning`, `info`, `hint`, `off` |
| `message` / `note` | diagnostic text |
| `rule` | the matcher (below) |
| `constraints` | per-metavariable filters (`regex`, `kind`, `pattern`), applied after the rule matches |
| `transform` | derive new metavariables (`replace`, `substring`, `convert` case) for use in `fix` |
| `fix` | replacement template using metavariables; string or `{template, expandStart, expandEnd}` |
| `utils` | named sub-rules referenced with `matches: <name>` |
| `files` / `ignores` | globs limiting where the rule applies |

## Matchers

| Kind | Keys | Notes |
|---|---|---|
| atomic | `pattern`, `kind`, `regex`, `nthChild`, `range` | `pattern` may be an object `{context, selector}` for fragments that do not parse alone |
| relational | `inside`, `has`, `follows`, `precedes` | default search depth is one level; `stopBy: end` searches all ancestors/descendants; `field:` restricts to a named child |
| composite | `all`, `any`, `not`, `matches` | a rule object with several keys is an implicit `all` |

Metavariables: `$A` one named node; `$$$A` zero or more nodes (arguments, statements); `$_` matches
without capturing; `$$A` also matches unnamed nodes (punctuation). Reusing `$A` inside a relational
sub-rule requires the same text as the first binding.

Constraints are checked after the whole rule matched. A `has` sub-rule returns the first node that
satisfies it and does not backtrack when a constraint later fails; put the filter (`not`, `regex`)
inside the sub-rule itself.

Use `--debug-query=ast` (or `cst`, `sexp`) to see node kinds and field names before writing
`kind:` / `field:` rules:

```bash
ast-grep run -l python -p 'from datetime import datetime as dt' --debug-query=ast
# import_from_statement
#   module_name: dotted_name
#   name: aliased_import
#     name: dotted_name
#     alias: identifier
```

## Tested example: `utcnow()` migration (rules/utcnow.yml)

```yaml
id: utcnow-qualified
language: python
severity: error
message: datetime.datetime.utcnow() is deprecated; use datetime.datetime.now(datetime.UTC)
rule:
  pattern: datetime.datetime.utcnow()
fix: datetime.datetime.now(datetime.UTC)
---
id: utcnow-class
language: python
severity: error
message: datetime.utcnow() is deprecated; use datetime.now(UTC)
rule:
  pattern: $CLS.utcnow()
  inside:
    kind: module
    stopBy: end
    has:
      kind: import_from_statement
      all:
        - has: { field: module_name, regex: '^datetime$' }
        - any:
            - has: { field: name, pattern: $CLS }
            - has:
                kind: aliased_import
                all:
                  - has: { field: name, regex: '^datetime$' }
                  - has: { field: alias, pattern: $CLS }
constraints:
  CLS: { regex: '^\w+$' }
fix: $CLS.now(UTC)
---
id: utcnow-add-utc-import
language: python
severity: hint
message: add `from datetime import UTC` next to the existing datetime import
rule:
  all:
    - kind: import_from_statement
    - has: { field: module_name, regex: '^datetime$' }
    - pattern: $STMT
    - inside:
        kind: module
        stopBy: end
        all:
          - has:
              stopBy: end
              pattern: $C.utcnow()
              not: { pattern: datetime.datetime.utcnow() }
          - not:
              has:
                stopBy: end
                kind: import_from_statement
                has: { field: name, regex: '^UTC$' }
fix: |-
  $STMT
  from datetime import UTC
```

Why the third rule filters with `not` inside `has` rather than a constraint on `$C`: in a module
containing both `datetime.datetime.utcnow()` and `dt.utcnow()`, a constraint would see the first
`has` binding (`datetime.datetime`), fail, and skip the module.

The import rule appends a separate `from datetime import UTC` line; run
`ruff check --select I,F401 --fix` afterwards to merge it into the existing import.
All three rules apply in one `ast-grep scan -U` pass and a second pass changes nothing.

## Tests (rule-tests/)

```yaml
# rule-tests/utcnow-class-test.yml
id: utcnow-class
valid:
  - |
    from datetime import UTC, datetime
    datetime.now(UTC)
  - |
    import arrow
    arrow.utcnow()
invalid:
  - |
    from datetime import datetime
    datetime.utcnow()
  - |
    from datetime import datetime as dt
    dt.utcnow()
```

```yaml
# rule-tests/utcnow-add-utc-import-test.yml
id: utcnow-add-utc-import
valid:
  - |
    from datetime import UTC, datetime
    datetime.utcnow()
  - |
    import datetime
    datetime.datetime.utcnow()
invalid:
  - |
    from datetime import datetime, timedelta
    datetime.utcnow()
  - |
    import datetime
    from datetime import datetime as dt
    datetime.datetime.utcnow()
    dt.utcnow()
```

```bash
ast-grep test -c tools/codemods/sgconfig.yml --skip-snapshot-tests   # match/no-match only
ast-grep test -c tools/codemods/sgconfig.yml -U                      # write __snapshots__ (fixed output)
ast-grep test -c tools/codemods/sgconfig.yml                         # CI: compares against snapshots
```

Snapshot files record the `fixed:` output per invalid case; review them like code.

## Not covered by these rules (handle as residue)

- Function references: `field(default_factory=datetime.utcnow)`, `Column(default=datetime.utcnow)`.
  Find with `ast-grep run -l python -p '$C.utcnow'` (attribute without call) or
  `rg -n 'utcnow\b[^(]'`; rewrite to `lambda: datetime.now(UTC)`.
- `utcfromtimestamp(ts)` (also deprecated since 3.12): separate rule to
  `datetime.fromtimestamp(ts, UTC)`; ruff flags it as DTZ004.
- Comparisons and arithmetic between the now-aware values and naive values from storage or
  third-party APIs: only tests reveal them.

## Other useful rule shapes

```yaml
# rename a keyword argument (and convert its unit) only in calls to fetch / x.fetch
id: timeout-kwarg
language: python
rule:
  kind: keyword_argument
  all:
    - has: { field: name, regex: '^timeout_ms$' }
    - has: { field: value, pattern: $V }
  inside:
    kind: argument_list
    inside:
      kind: call
      has: { field: function, regex: '(^|\.)fetch$' }
fix: timeout=($V) / 1000
```

Matching the `keyword_argument` node works wherever the argument sits. The tempting pattern
`$F($$$PRE, timeout_ms=$V, $$$POST)` only matched calls with arguments on both sides (the commas
are literal), and `$V / 1000` without parentheses turns `a + b` into `a + b / 1000`.

```yaml
# flag (no fix) a banned call outside tests
id: no-print
language: python
severity: error
message: use the logger
rule:
  pattern: print($$$ARGS)
ignores: ["tests/**", "scripts/**"]
```

Check every new shape with `ast-grep test` before running it over the repository; trailing commas
and comments between arguments are where `$$$` patterns most often surprise.
