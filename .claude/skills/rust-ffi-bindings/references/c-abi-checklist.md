# C ABI checklist, Rust-to-C exports, callbacks and C++

Use with SKILL.md sections 2-4. Unsafe code is correct only if the safe API around it is sound
for every input and every safe caller. The generic unsafe audit procedure (operation contracts,
validity invariants, Miri flags) lives in the `rust-unsafe-soundness` skill; this file is the
FFI-specific part.

## 1. Review checklist

Types and layout
- [ ] Every type crossing the boundary is `#[repr(C)]`, a `#[repr(transparent)]` newtype, or a
      `core::ffi` primitive (`c_int`, `c_char`, `c_void`, `c_long`, ...). Rust 1.98 made
      `repr(transparent)` stricter about which extra fields count as trivial.
- [ ] Rust enums never receive values from C unless every possible value is a declared variant;
      receive the integer and convert with `TryFrom`.
- [ ] `bool` only if the C side uses `_Bool`/`bool`.
- [ ] Optional pointers are `Option<NonNull<T>>`, `Option<&T>` or `Option<extern "C" fn(..)>`
      (null-pointer optimisation guaranteed for these).
- [ ] Generated bindings are checked in or generated in `build.rs` against a pinned header
      version; bindgen's layout tests run in CI on every shipped target.
- [ ] Foreign opaque types: bindgen emits `pub struct foo_ctx { _unused: [u8; 0] }`; hand-written
      equivalents add `_marker: PhantomData<(*mut u8, PhantomPinned)>` so Rust cannot construct,
      move or auto-`Send` them.

Strings and buffers
- [ ] Incoming `*const c_char`: `CStr::from_ptr` requires NUL termination and validity for the
      call's duration; convert to owned (`to_str()?.to_owned()` or `to_string_lossy().into_owned()`).
- [ ] Outgoing strings: `CString::new(s)?` (fails on interior NUL); keep the `CString` alive while
      C uses the pointer, or transfer with `into_raw` + a Rust free function.
- [ ] Buffers carry explicit lengths; never trust a C-provided length without bounds checks.
- [ ] `slice::from_raw_parts(p, n)`: `p` non-null and aligned even for `n == 0`,
      `n * size_of::<T>() <= isize::MAX`, one allocation, initialised, not mutated meanwhile.

Ownership and allocation
- [ ] Memory is freed by the allocator that allocated it. Objects from `Box::into_raw` come back
      through a Rust `extern "C" fn foo_free(p)` that null-checks and calls `drop(Box::from_raw(p))`.
      (`Box::into_non_null` / `Box::from_non_null` are stable since 1.99.)
- [ ] Callbacks with `void *user_data`: document the lifetime; the Rust closure must outlive every
      invocation; check which thread calls back (`Send` requirements).

Unwinding and errors
- [ ] Exported functions either cannot panic or wrap the body in `catch_unwind` and map to an
      error code. Since Rust 1.81 a panic escaping `extern "C"` aborts.
- [ ] Imports from code that can unwind (C++ exceptions) are declared `extern "C-unwind"`
      (stable since 1.71). `longjmp` across Rust frames is never acceptable.
- [ ] `errno` read immediately after the call with `std::io::Error::last_os_error()`.

Threads and globals
- [ ] Library thread-safety documented and respected: global init once (`OnceLock`), per-thread
      contexts not shared, `!Send` wrappers for thread-affine handles (UI toolkits, some GPU APIs).
- [ ] `unsafe impl Send/Sync` carry a SAFETY comment quoting the C library's thread rules.
- [ ] Edition 2024: `unsafe extern "C" { pub fn f(x: c_int) -> c_int; }`; mark an item
      `pub safe fn` only when calling it is sound for all inputs; exports use `#[unsafe(no_mangle)]`.

## 2. Exposing Rust to C (cdylib/staticlib + cbindgen)

```toml
[lib]
crate-type = ["cdylib", "staticlib", "rlib"]   # rlib keeps `cargo test` working
```

```toml
# cbindgen.toml
language = "C"
include_guard = "BAR_CAPI_H"
autogen_warning = "/* Generated by cbindgen. Do not edit. */"
```

```bash
cargo install --locked cbindgen
cbindgen --config cbindgen.toml --crate bar-capi --output include/bar.h
git diff --exit-code include/bar.h          # CI: header must match the code
```

Or from `build.rs` (adds a build dependency on cbindgen):

```rust
let dir = std::env::var("CARGO_MANIFEST_DIR").unwrap();
cbindgen::Builder::new().with_crate(dir).with_language(cbindgen::Language::C)
    .generate().expect("cbindgen").write_to_file("include/bar.h");
```

Handle API (compiles clean with `clippy::undocumented_unsafe_blocks` and `missing_safety_doc`):

```rust
pub struct BarParser { lines: u64 }   // cbindgen: `typedef struct BarParser BarParser;`

#[unsafe(no_mangle)]
pub extern "C" fn bar_parser_new() -> *mut BarParser {
    catch_unwind(|| Box::into_raw(Box::new(BarParser { lines: 0 }))).unwrap_or(ptr::null_mut())
}

/// # Safety
/// `p` is NULL or came from `bar_parser_new` and is not used afterwards.
#[unsafe(no_mangle)]
pub unsafe extern "C" fn bar_parser_free(p: *mut BarParser) {
    if !p.is_null() {
        // SAFETY: caller contract: `p` is a live pointer from Box::into_raw, freed once.
        drop(unsafe { Box::from_raw(p) });
    }
}
```

Test the C surface from Rust (`c"hello".as_ptr()`), and from a small C program linked against
the staticlib (`cargo rustc -- --print native-static-libs` lists the extra `-l` flags) under ASan.

## 3. Callbacks with user data (verified pattern)

```rust
type Callback = unsafe extern "C" fn(user_data: *mut c_void, value: c_int);
unsafe extern "C" { fn lib_for_each(cb: Option<Callback>, user_data: *mut c_void); }

extern "C" fn trampoline<F: FnMut(c_int)>(user_data: *mut c_void, value: c_int) {
    let _ = catch_unwind(AssertUnwindSafe(|| {
        // SAFETY: `user_data` is the `&mut F` passed by `for_each`, alive for the whole call.
        let f = unsafe { &mut *user_data.cast::<F>() };
        f(value);
    }));
}

pub fn for_each(mut f: impl FnMut(c_int)) {
    fn erase<F: FnMut(c_int)>(f: &mut F) -> (Callback, *mut c_void) {
        (trampoline::<F>, (f as *mut F).cast())
    }
    let (cb, data) = erase(&mut f);
    // SAFETY: the library calls `cb` synchronously; `f` outlives this call.
    unsafe { lib_for_each(Some(cb), data) };
}
```

If the library stores the callback (asynchronous), box the closure (`Box<dyn FnMut + Send>`),
pass `Box::into_raw`, and free it in an unregister/destroy hook; never pass a stack reference.

## 4. C++ with cxx

```rust
#[cxx::bridge(namespace = "demo")]
mod ffi {
    struct BlobMetadata { size: usize, tags: Vec<String> }      // shared, both sides see it
    extern "Rust" { type MultiBuf; fn next_chunk(buf: &mut MultiBuf) -> &[u8]; }
    unsafe extern "C++" {
        include!("demo/include/blobstore.h");
        type BlobstoreClient;
        fn new_blobstore_client() -> UniquePtr<BlobstoreClient>;
        fn put(&self, parts: &mut MultiBuf) -> u64;
    }
}
```

```rust
// build.rs
cxx_build::bridge("src/main.rs").file("src/blobstore.cc").std("c++17").compile("demo");
println!("cargo::rerun-if-changed=src/blobstore.cc");
println!("cargo::rerun-if-changed=include/blobstore.h");
```

- cxx checks signatures on both sides at build time; C++ exceptions thrown through a bridge
  function abort unless the function returns `Result<T>` (then they become `Err`).
- autocxx (`include_cpp! { #include "x.h" safety!(unsafe_ffi) generate!("Class") }`) generates
  the bridge from headers; use it for large existing C++ APIs, cxx for hand-curated surfaces.

## 5. Linking diagnostics

| Symptom | Check |
|---|---|
| `undefined reference to foo_*` | build script emitted `cargo::rustc-link-lib=foo` and a `rustc-link-search`; `cc::Build::compile` emits both |
| links the wrong copy (system vs vendored) | `cargo build -vv` and read the `-l`/`-L` flags; env override such as `FOO_NO_VENDOR` must be in `rerun-if-env-changed` |
| two crates link the same C library | add `links = "foo"` so Cargo errors early instead of at link time |
| staticlib consumer misses system libs | `cargo rustc --crate-type staticlib -- --print native-static-libs` |
| macOS "built for newer macOS version" warnings | set `MACOSX_DEPLOYMENT_TARGET` consistently for cc and rustc |
